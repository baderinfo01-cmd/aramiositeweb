# دليل التشغيل على جهازك ثم الرفع على الاستضافة

> يغطي هذا الدليل: (1) تشغيل الموقع محليًا، (2) تفعيل الذكاء الاصطناعي، (3) الرفع إلى Hostinger، (4) قائمة الأمان التي يجب تنفيذها **اليوم**.

---

## 0) ⚠️ تنبيهات أمنية عاجلة (قبل أي شيء)

1. **غيّر كلمة مرور قاعدة البيانات** من لوحة Hostinger (Databases → Manage → Change password). كانت كلمة المرور القديمة مكتوبة داخل `includes/db.php` ومرفوعة على GitHub داخل الملف المضغوط.
2. **غيّر كلمة مرور حساب الأدمن** (`admin@aramio.com`). الملف القديم `fix_admin.php` كان يُنشئ الحساب بكلمة مرور معروفة (`123456`) ويطبعها على الشاشة، وكان أي زائر يستطيع فتح الرابط وإعادة ضبط حساب المدير!
   ```bash
   php tools/set_password.php admin@aramio.com "كلمة_قوية_جديدة_123"
   ```
   أو من phpMyAdmin بعد تشغيل `tools/set_password.php` محليًا على نسخة من القاعدة.
3. **احذف الملف المضغوط `موقع ارميوا.zip` من مستودع GitHub** (يحتوي كلمة مرور القاعدة ونسخة SQL فيها بيانات مستخدمين حقيقيين). إن كان المستودع **عامًّا (Public)** فاجعله **Private** فورًا، وافترض أن البيانات القديمة قد اطُّلع عليها: غيّر كل كلمات المرور واطلب من المدربين تغيير كلماتهم (كلمة المرور الموحدة `Aramio@2026` كانت في `add_experts.php`).
4. **احذف من الاستضافة الملفات الخطرة القديمة** (إن وُجدت): `fix_admin.php`, `add_experts.php`, `legacy_certs.php` (في الجذر), `trainee/request_exam.php`, والمجلدات `admin/includes`, `trainer/includes`, `trainee/includes`.

## 1) المتطلبات

| العنصر | الإصدار |
|---|---|
| PHP | **7.4 أو أحدث** (يُنصح 8.1+) مع امتدادات: `pdo_mysql`, `mbstring`, `curl`, `fileinfo`, `openssl`, `gd` |
| قاعدة البيانات | MariaDB 10.3+ / MySQL 5.7+ (Hostinger يستخدم MariaDB) |

لا حاجة لـ Composer أو npm: كل المكتبات (Bootstrap, Font Awesome, Swiper, Chart.js, الخطوط) **مضمّنة محليًا** داخل `assets/vendor` فيعمل الموقع حتى بلا إنترنت (باستثناء صور الأفاتار الافتراضية من ui-avatars).

## 2) التشغيل على جهازك

### الطريقة أ — XAMPP (ويندوز، الأسهل)
1. ثبّت [XAMPP](https://www.apachefriends.org) وشغّل **Apache** و **MySQL** من لوحة التحكم.
2. انسخ محتويات مجلد `public_html` من المستودع إلى `C:\xampp\htdocs\aramio\`.
3. افتح `http://localhost/phpmyadmin` ← **New** ← أنشئ قاعدة باسم `aramio_dev` بترميز `utf8mb4_unicode_ci`.
4. اختر القاعدة ← **Import** ← ارفع ملف `u846492886_a.sql` (نسخة قاعدة بياناتك الحالية. **لا ترفعه إلى GitHub**).
5. بعدها **Import** مرة أخرى للملف `database/upgrade_v2.sql` (ترقية آمنة: تضيف جداول جديدة فقط وتصلح جدول أرباح الاستشارات).
6. في `C:\xampp\htdocs\aramio\includes\` انسخ `config.sample.php` إلى `config.local.php` وعدّله:
   ```php
   'db_host' => '127.0.0.1', 'db_name' => 'aramio_dev', 'db_user' => 'root', 'db_pass' => '',
   'base_url' => 'http://localhost/aramio', 'debug' => true,
   ```
   (`debug => true` يُظهر رمز التفعيل وروابط استعادة كلمة المرور على الشاشة لأن XAMPP لا يرسل بريدًا — **اجعلها `false` على الاستضافة**).
7. افتح `http://localhost/aramio/`. ادخل بحساب الأدمن (أو أعد ضبط كلمة مروره بالأمر أعلاه).

### الطريقة ب — خادم PHP المدمج (ماك/لينكس/ويندوز مع PHP)
```bash
# قاعدة بيانات محلية (مثال MariaDB)
mysql -uroot -e "CREATE DATABASE aramio_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysql -uroot aramio_dev < u846492886_a.sql
mysql -uroot aramio_dev < database/upgrade_v2.sql
cp public_html/includes/config.sample.php public_html/includes/config.local.php   # ثم عدّل البيانات
cd public_html && php -S localhost:8080
```
ثم افتح `http://localhost:8080`.

## 3) تفعيل الذكاء الاصطناعي

الموقع مبني **بطبقة مستقلة عن المزوّد** — اختر أيًّا من: Anthropic (Claude)، OpenAI، Google Gemini، أو أي خدمة متوافقة مع OpenAI (DeepSeek, Groq, OpenRouter, Ollama المحلي…).

**من لوحة التحكم (الأسهل):** الأدمن ← الإعدادات العامة ← تبويب **الذكاء الاصطناعي** ← اختر المزوّد وأدخل مفتاح API ← حفظ ← **اختبار الاتصال**. يُخزَّن المفتاح **مشفّرًا** في قاعدة البيانات (يعتمد التشفير على `app_secret` في `config.local.php` — اجعله نصًا عشوائيًا طويلًا ولا تغيّره لاحقًا).

**أو من الملف:** في `config.local.php`: `'ai_provider' => 'anthropic', 'ai_api_key' => 'sk-...', 'ai_model' => ''` (يتغلّب على إعدادات اللوحة).

بدون مفتاح يعمل الموقع بشكل طبيعي، ويتحول المساعد إلى توصية بالكلمات المفتاحية.

### ما الذي يفعله الذكاء الاصطناعي في الموقع؟
| الجهة | الميزة |
|---|---|
| الزائر | مساعد دردشة عائم يعرف دوراتك وأسئلتك الشائعة · "رشّح لي دورة" في الرئيسية |
| المتدرب | **المعلّم الذكي** (تلخيص، شرح مبسّط، اختبارني، خطة دراسة) داخل كل دورة اشترك بها · اختبارات تفاعلية بدرجة وشرح |
| المدرب | كاتب وصف الدورة (عربي+إنجليزي) · مخطط دروس · **منشئ اختبارات** · ترجمة الدورة وحفظها بـ 4 لغات · منشورات ترويجية · SEO · تحسين النبذة |
| الأدمن | استوديو الذكاء الاصطناعي · تحليل أداء الأكاديمية بخطوات مقترحة · مسودة رد على رسائل الزوار · توليد إشعارات منبثقة · مساعد داخل اللوحة |

حماية: حدّ أقصى للطلبات (Rate limit) لكل مستخدم/عنوان، وتسجيل الاستخدام في **الأدمن ← سجل الأمان**، ولا يُرسل إلى المزوّد أي بيانات شخصية للمستخدمين الآخرين.

## 4) الرفع على Hostinger

1. **انسخ احتياطيًا** (نسخة من الملفات + تصدير قاعدة البيانات من phpMyAdmin).
2. من **File Manager** (أو FTP) ارفع محتويات المجلد `public_html` من المستودع إلى `public_html` في الاستضافة **مع الإبقاء على مجلد `uploads` الحالي** (لا تستبدله — فيه صور المتدربين والإيصالات؛ الموقع الجديد يضيف فقط ملف `.htaccess` يمنع تنفيذ PHP داخله).
3. أنشئ `includes/config.local.php` على الاستضافة (من `config.sample.php`) بالبيانات الحقيقية:
   ```php
   'db_host'=>'localhost','db_name'=>'u846492886_a','db_user'=>'u846492886_a','db_pass'=>'<كلمة المرور الجديدة>',
   'base_url'=>'https://aramiosmartglobal.com','debug'=>false,'app_secret'=>'<نص عشوائي طويل>','mail_from'=>'no-reply@aramiosmartglobal.com'
   ```
   > **مهم:** بدون هذا الملف سيعرض الموقع رسالة "Configuration missing". (الأفضل أمنيًا وضعه خارج `public_html` باسم `aramio_config.php` في مجلد الحساب الرئيسي — الموقع يبحث هناك أولًا.)
4. في **phpMyAdmin** ← اختر قاعدتك ← **Import** ← `database/upgrade_v2.sql`. (آمن: لا يحذف ولا يعدّل بياناتك، وهو قابل للتشغيل أكثر من مرة.)
5. من إعدادات PHP في Hostinger اختر **PHP 8.1 أو أحدث**.
6. فعّل شهادة SSL ثم فعّل تحويل HTTPS بإزالة علامة `#` من سطري `RewriteCond/RewriteRule` داخل `.htaccess`.
7. أنشئ مجلدات الرفع إن لم توجد: `uploads/courses`, `uploads/receipts`, `uploads/avatars`, `uploads/reviews`, `uploads/gallery` (صلاحية 755).
8. افتح الموقع وجرّب: الرئيسية ← تسجيل جديد (يصل رمز التفعيل بالبريد) ← دخول الأدمن ← الإعدادات ← الذكاء الاصطناعي.
9. **البريد:** رمز التفعيل واستعادة كلمة المرور يُرسلان بدالة `mail()`. تأكد من وجود صندوق بريد `no-reply@aramiosmartglobal.com` في Hostinger وأن سجلات SPF/DKIM مفعّلة كي لا تذهب الرسائل إلى الرسائل المزعجة.
10. أضف الموقع إلى Google Search Console وأرسل `https://aramiosmartglobal.com/sitemap.php`.

## 5) ماذا تغيّر؟ (ملخص)

### الأمان (أخطر ما كان في النسخة القديمة)
- حذف `fix_admin.php` و `add_experts.php` (إعادة ضبط الأدمن علنًا + كلمات مرور افتراضية).
- كلمة مرور القاعدة خرجت من الكود إلى `config.local.php` (خارج Git).
- **حماية CSRF** لكل النماذج، وتحويل كل الإجراءات الخطرة (حذف/رفض/تفعيل) من روابط `GET` إلى `POST` محمية.
- إصلاح ثغرات **SQL Injection** (مثل `consultations.php`, `settings.php`, `store.php`) باستخدام استعلامات مهيّأة.
- **رفع الملفات:** كان الإيصال يُحفظ بامتداده الأصلي (إمكانية رفع `.php` وتنفيذ أوامر على السيرفر). الآن: فحص النوع الحقيقي، اسم عشوائي، ومنع تنفيذ PHP في `uploads/`.
- **التلاعب بالأسعار:** كان مبلغ الدفع يأتي من حقل مخفي في المتصفح؛ الآن يُقرأ من قاعدة البيانات.
- رمز التفعيل لم يكن يُرسل بالبريد بل **يظهر على الشاشة** للجميع؛ الآن يُرسل بالبريد فقط.
- تحديد محاولات الدخول، `session_regenerate_id`، كوكيز آمنة، ترويسات أمان، تدقيق كلمات المرور (8+ أحرف وأرقام)، سجل نشاط، استعادة كلمة مرور بروابط مؤقتة.
- منع الاعتماد المزدوج للطلب (كان يمكن تكرار عمولة المدرب).
- إصلاح خلل: تأكيد دفع الاستشارة كان يفشل لأن عمود `booking_id` غير موجود (يضيفه `upgrade_v2.sql`).

### الواجهة العامة
تصميم جديد كليًا (وضع داكن، متجاوب بالكامل، حركات خفيفة) · **6 لغات** (العربية، الإنجليزية، الفرنسية، التركية، الإسبانية، الملايو) · صفحة تفاصيل الدورة (كانت مفقودة؛ كان الرابط يعيد قائمة الدورات) · تحقق الشهادات بـ **QR** وشهادة قابلة للطباعة · **PWA** (تثبيت كتطبيق + وضع عدم الاتصال) · SEO (بيانات منظّمة JSON-LD، sitemap، hreflang، Open Graph) · أسئلة شائعة وقوائم بريدية.

### لوحات التحكم (أدمن / مدرب / متدرب)
هيكل موحّد (قائمة جانبية، إشعارات داخلية، وضع داكن، مساعد ذكي) · **أدمن:** رسوم بيانية للإيرادات والنمو، فلترة وتصدير CSV، سجل أمان، استوديو AI، أرشيف الشهادات مع استيراد CSV · **مدرب:** رسوم أرباح، **اختبارات بالذكاء الاصطناعي**، أدوات ترويج وترجمة · **متدرب:** مشغّل دروس مع تتبّع التقدم، اختبارات بنتائج وشرح، شهادات قابلة للمشاركة، توصيات مخصصة.

### ملاحظات سلوكية
- أسعار الدولار↔الدينار في الواجهة العامة تستخدم الآن «سعر الصرف» من الإعدادات (كان 135 ثابتًا في الكود بينما اللوحة تستخدم الإعداد).
- لوحات التحكم بالعربية والإنجليزية؛ بقية اللغات تعرض الإنجليزية داخل اللوحات، أما الواجهة العامة فبالست لغات. محتوى الدورات يُترجم إلى fr/tr/es/ms بزر الذكاء الاصطناعي (يُخزَّن في جدول `translations`).
- صفحة «من نحن»: نصوص الأقسام بالعربية والإنجليزية (من ملفاتك الأصلية)، وتظهر للغات الأخرى بالإنجليزية.
- الموظف (`staff`) لا يرى صفحات: المستخدمين، الإعدادات، المصاريف، سجل الأمان (للأدمن فقط).

## 7) استكشاف الأخطاء
| العَرَض | الحل |
|---|---|
| «Configuration missing» | أنشئ `includes/config.local.php` |
| «Service temporarily unavailable» | بيانات القاعدة خاطئة في `config.local.php` |
| الصفحة بيضاء | فعّل `'debug'=>true` مؤقتًا أو راجع سجل أخطاء PHP في Hostinger |
| لا يصل رمز التفعيل | تحقق من بريد `mail_from` وSPF؛ ومحليًا استخدم `debug=>true` |
| «DB error — did you run upgrade_v2.sql?» عند تأكيد الاستشارة | نفّذ `database/upgrade_v2.sql` |
| الذكاء الاصطناعي لا يرد | الإعدادات ← الذكاء الاصطناعي ← **اختبار الاتصال**؛ تأكد من رصيد/مفتاح المزوّد ومن أن الاستضافة تسمح باتصالات `curl` الخارجية |
